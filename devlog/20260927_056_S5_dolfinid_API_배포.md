## 0. 결정

- **S2(버전)보다 배포를 먼저** 했다(요청). S2 는 착수 전이라 잃은 작업은 없다.

  - 이유: dolfinid 의 다른 서비스(fcmanager 등)와 같은 구성(컨테이너 하나, gunicorn, WhiteNoise)이 되고,
    목적이 바뀌어 웹에 필요한 화면이 적다(로그인 · 앙상블/초대 · 악보 올리기 · TV 코드 입력).

## 1. 코드 변경

### 서버 디스크 파일 저장소 (`STORAGE_BACKEND=local`)
054 §8 결정(파일 = VM 디스크, 받기 = nginx X-Accel-Redirect)의 구현.
- `LocalStorageHandler` — S3Handler 와 같은 메서드. `get_storage()` 가 설정으로 고른다. 키 모양은 S3 와 같고 FILES_ROOT 밖으로 못 나간다(경로 검사)
- 서명 토큰 URL `/api/v1/files/blob/<token>/` (Django signing, 만료 포함, 쿠키 · JWT 없이 토큰이 권한)
  - **PUT** = 업로드: 예약 때 만든 키에만, **한 번만**(있으면 409), `MAX_UPLOAD_SIZE` 초과 시 413, 임시 파일 → rename
  - **GET** = 받기: 토큰만 확인하고 `X-Accel-Redirect: /_protected/<key>` → nginx 가 디스크에서 보낸다(파일이 gunicorn 을 안 지난다)
  - 만료 시각을 창 단위로 올림해 같은 파일의 URL 이 한동안 같다 → 목록을 다시 불러도 썸네일이 브라우저 캐시에서
- **인증 없이 키만으로 썸네일을 주던 `files/thumbnail/<key>` 를 없앴다**(055 §4 에서 남겨 둔 구멍). `thumbnail_url` 은 6시간짜리 서명 URL
- `direct-download` 는 파일을 Django 로 흘리던 것을 서명 URL 로 302
- PDF 작업: presigned URL 을 만들어 HTTP 로 받던 것을 저장소에서 바로 읽고 쓴다(`read_bytes`/`write_bytes`). `process_pdf_info` 가 **SHA-256** 을 채운다(S4 동기화에서 TV 가 받은 파일 확인용)

### 운영 설정
- Django **5.0(지원 종료) → 5.2 LTS**, whitenoise, gunicorn. 운영 의존성은 `backend/requirements-prod.txt`(버전 고정, 테스트 도구 없음)
- `REQUIRE_SECRET_KEY` — 개발용 · 50자 미만 키로는 뜨지 않는다(JWT 서명 키이기도 하다)
- `CSRF_TRUSTED_ORIGINS`, `TRUST_PROXY_HEADERS`, 보안 쿠키, HSTS 를 환경변수로. SSL 리다이렉트는 nginx 담당
- 로그는 콘솔만(`LOG_DIR` 을 주면 파일도) — 운영 컨테이너 루트는 읽기 전용이고, 예전 설정은 import 시점에 `logs/` 를 만들었다
- SQLite: WAL · `timeout=20` · `transaction_mode=IMMEDIATE` (gunicorn 2 × 4 스레드)
- CORS: `CORS_ALLOWED_ORIGIN` 이 있을 때만(개발 웹용). 운영은 같은 출처
- `/healthz` — 버전 · DB · 행 수(user · score · ensemble) · 무결성 센티넬. ok 200 / degraded 200 / unhealthy 503 (operations.md §4)

## 2. `deploy/` — fcmanager 계약을 그대로

|---|---|

| `remote-prod.sh` | `ssh honestjung@cdgts.paleobytes.info /srv/scoremate/deploy-prod.sh X.Y.Z` (대상은 파일에 고정) |
| `host/_extract_and_deploy.sh` | 이미지에서 host 파일 추출(bash -n 통과 시에만, `.previous` 보존) — 운영은 git-free |
| `host/deploy.sh` | pull → `.env` IMAGE_TAG 만 → down → pre-deploy 스냅샷(+.mig) → up → healthz → **DB · 파일 바인딩 게이트(경로 + 쓰기 프로브)** → smoke |
| `host/smoke.sh` · `rollback.sh` · `prune.sh` | healthz ok + 버전 + user>0 / keep(기본) · restore(무결성 검사 후) / 이 서비스 이미지만 정리 |

## 3. 배포 기록

1. **build 0.1.0 첫 시도 — 이미지 스모크가 push 전에 막았다**: `ModuleNotFoundError: files.utils`.
   파일 저장소 마운트 `/app/files` 가 Django 앱 `files` 패키지 디렉터리를 덮었다 → `/app/hostfiles` 로. 스모크 단계를 넣은 값을 바로 했다
2. dolfinid 설치: `/srv/scoremate/{db,files,backup,acme,maintenance}`, 부트스트랩 파일은 이미지에서 `docker cp`, `.env` 는 서버에서 생성
   (비밀키 86자 · 관리자 비밀번호 — 출력하지 않았다, `/srv/scoremate/.env` 에만 있다)
3. nginx 1.24 — `http2 on;` 이 없는 판이라 `listen 443 ssl http2` 로. 80 블록 → `certbot certonly --webroot` → 전체 설정
4. `remote-prod.sh 0.1.0` → smoke PASS. hourly cron 등록, 첫 백업 OK
5. **외부 종단 확인**(임시 계정 2개): 가입 → 앙상블 → PDF(35쪽) PUT → 재사용 409 → confirm(앙상블 · 파트) →
   pages 35 · SHA-256 일치 → 목록 썸네일(X-Accel, image/jpeg) → 원본 받기(X-Accel, 해시 일치, 한글 파일명 헤더) →
   비멤버 404 → 악보 · 앙상블 삭제. `/_protected/` 직접 404, 옛 썸네일 경로 404, HTTP→HTTPS 301, HSTS · nosniff · DENY 확인
6. **발견 1 — 컨테이너 root 는 DB 에 못 쓴다**: `cap_drop: ALL` 이라 DAC_OVERRIDE 가 없어 honestjung 소유 DB 를 읽기 전용으로 연다 →
   WAL `init_command` 가 실패. 테스트 계정 삭제에서 드러났고, 같은 이유로 **deploy.sh · rollback.sh 의 migration 수 조회가 조용히 비어
   rollback keep 가드가 무력**했다. exec 를 DB 소유 uid 로(`-u "$(stat -c %u db)"`)
   - fcmanager 는 cap 을 안 떨어뜨려 이 문제가 없다. 경화(cap_drop)는 유지하고 exec 쪽을 고쳤다
7. **발견 2** — local 삭제가 빈 디렉터리를 남겼다 → 비면 위로 지운다
8. `0.1.1` 배포 → pre-deploy 스냅샷 + `.mig`(26) 기록 확인 → **rollback 0.1.0 --db=keep**(가드 "26=26 안전") → smoke → 0.1.1 재배포.
   롤백 동사까지 운영에서 한 번 돌렸다
