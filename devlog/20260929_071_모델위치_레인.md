# 071 — 모델 위치 레인: 모든 악보에 모델이 읽은 시스템 · 보표 · 마디선 (0.11.0)

작성일: 2026-09-29
상태: ✅ 구현 · 테스트 · 배포
실험: devlog 070(벡터 8쪽 개수 모두 일치, 평균 0.1~0.4pt)

## 요청
"모든 악보에 붙이는 레인 만들어줘"

## 구성
```
*/10 cron → scripts/model_layout_lane.sh   (flock, 악보 인식 레인과 따로 — 잠금 · 로그 · 작업 폴더가 다르다)
  1. manage.py model_layout_pending   → MLAYOUT_JOB {version_id, key, sha256, pages}   지금 판 · 해시 있음 · 아직 없음 · 짧은 것부터
  2. sha256 확인 → scripts/model_layout.py <pdf> omr/model_layout/v<id>
       쪽마다 한 번(200dpi, effort high): systems[{bbox, staves, barlines, staff_names, time_signatures}] (0..1000)
       쪽마다 검산(bbox 순서 · 첫/끝 보표 = bbox · 마디선 증가 · 끝선 = 오른쪽 끝 · 이름 수) → 틀리면 한 번 더 → 그래도면 종료 3
       쪽 결과는 pages/pNNN.json — 끊겨도 이어 한다
  3. result.json | manage.py model_layout_ingest
```
- 컨테이너(`scores/model_layouts.py`)
  - 0..1000 → pt: 쪽 크기는 PDF 분석과 같은 CropBox 규칙(`score_layout._page_box`)
  - `SystemLayout` · `TimeSignatureMark` → `score_layout.to_document` — **PDF 분석 파일과 같은 모양**(앱 ScoreLayout + measures · staves 행)
  - 추가 필드: `measured_by: model`
  - 마디선은 시스템 왼쪽 끝을 첫 값으로 넣는다(앱 규칙). 보표 이름이 "" 면 null
  - 저장: 분석 `model-layout` + `files/…/model_layout/v{N}.json`. 판 · 악보를 지우면 함께 지운다(`layout_key` — `omr.stored_keys`)
  - **검산** `agreement`: PDF 분석이 있으면 쪽마다 구조(시스템 · 보표 · 마디선 개수)가 같은지 본다. 같은 쪽은 테두리 · 오선 · 마디선의 pt 오차(평균 · 최대)를 남기고, 다른 쪽 번호도 남긴다
- 기기 동기화(`layouts.delivered_layout`)
  - PDF 분석이 시스템을 찾았으면 PDF 분석(`source: pdf`)
  - 못 찾았으면(스캔 · 모르는 작성기) 모델 위치(`source: model`)
  - `GET /scores/{id}/layout/` 도 같은 규칙이다
- 웹 상세: "위치(모델): N시스템 · M마디 — PDF 분석과 a/b쪽 같음, 평균 오차 x pt"
  - PDF 분석이 없으면 "기기에는 이 위치가 내려갑니다"
