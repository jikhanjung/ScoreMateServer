# 072 — 악보 처리 파이프라인 하나로: ① PDF 분석 → ② 모델 위치 → ③ 악보 인식 (0.12.0)

작성일: 2026-09-29
상태: ✅ 구현 · 테스트 · 배포

## 계기
사용자: "레인을 각각 따로 돌리지 말고 크론에서 스크립트 실행시켜서 그 스크립트 하나가 새로 올라온 파일을 잡고 단계별로 분기해서 처리하는 게 좋을 것 같은데."

세 레인(`layout_lane` 5분 · `omr_lane` 10분 · `model_layout_lane` 10분)의 문제:
- **순서를 보장하지 못했다.** 스캔본은 ③이 ②를 기다리지 않아 보표 수 · 시스템 수 검사와 줄 · 쪽 바뀜 확정을 못 받았다
- **검산 시점이 엇갈렸다.** ②를 받을 때만 계산해서, ①이 늦거나 다시 분석되면 비거나 낡았다
- 로그 · 잠금 · 상태가 세 군데였다

## 결정: 모든 악보 ① → ② → ③, 일의 단위는 쪽
- ② 를 ③ 보다 먼저 하는 이유(벡터도)
  - ②는 ③의 10~15% 비용이다
  - ③이 쓸 힌트(①)를 먼저 검산할 수 있다
  - 분기가 "①에 시스템이 있나" 하나로 준다
- 판 하나를 끝까지 쥐지 않는다
  - 42쪽 인식(1~2시간) 동안 새 악보의 1분짜리 단계가 기다리지 않게, **쪽마다 할 일을 다시 고른다**
  - 우선순위: ① 전부 → ② 한 쪽 → ③ 한 쪽 → 다시(짧은 악보부터)
- 모델 호출은 한 번에 하나다(구독 한도에 안전)

## 구현
- 호스트 `scripts/score_pipeline.py` + cron 셸 `deploy/host/score_pipeline.sh`(5분, flock, nvm PATH, venv)
  - 컨테이너에 `manage.py pipeline_status` 로 남은 일(판마다 pdf · model · omr 상태 · 힌트)을 묻는다
    → ①이 필요하면 `score_layout`
    → 아니면 ② 한 쪽(`model_layout.py --budget-pages 1`)
    → 아니면 ③ 한 쪽(`astra_musicxml.py --budget-pages 1 --staves --page-systems`)
    → 할 일이 없으면 끝(최대 3시간)
  - 종료 코드
    - 4 = 쪽 하나 끝남, 남음 → 진행 알림 · 다시 고르기
    - 0 · 3 = 끝(성공 · 판정 실패) → `model_layout_ingest` / `omr_ingest`
    - 그 밖: codex 로그인 문제면 **파이프라인 멈춤**(실패 기록 안 함). 아니면 그 판을 이번 실행에서 건너뛰고, 3번째에 실패 기록
  - 쪽마다 `manage.py pipeline_progress <판> model|omr <끝난 쪽> <전체>`(캐시 6시간) → 상세 "처리" 줄
- 두 모델 스크립트에 `--budget-pages N`(새로 한 쪽이 N 이면 종료 4)
  - 이미 쪽 단위로 이어 할 수 있어서 작은 변경이다
  - ②는 호출 수 · 시간 · 토큰을 `run.json` 에 쌓는다(여러 번에 나눠 돌므로)
- 컨테이너
  - `scores/pipeline.py`(단계 상태 · 남은 일 · 진행)
  - `layouts.pipeline_hints`: ③의 힌트
    - ①에 시스템이 있으면 ①. ②와 구조가 어긋난 쪽은 시스템 수 0 = 검사 안 함
    - 없으면(스캔) ②
  - `delivered_layout_document`: ③ 결과의 줄 · 쪽 바뀜을 ① 또는 ②로 확정
  - `layout_check`: 인식 마디 수가 위치 마디 수와 같은지
  - `model_layouts.refresh_agreement`: ①을 새로 분석할 때마다 ②의 검산을 다시 계산한다
- 없앤 것: 레인 셸 셋(`omr_lane.sh` · `layout_lane.sh` · `model_layout_lane.sh`)과 그 추출 규칙
  - 컨테이너 명령 `omr_pending` · `model_layout_pending` 은 손으로 볼 때 쓰도록 남겼다
- 웹 상세: "처리: ① PDF 분석 ✓ · ② 위치 4/13쪽 · ③ 악보 인식 — 5분마다 이어서 처리합니다"
  - 인식 칸의 "대기 N번째"는 지웠다
