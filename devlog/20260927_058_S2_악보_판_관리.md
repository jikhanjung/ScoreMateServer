## 1. 모델

```
ScoreVersion   score, number, s3_key, original_filename, size_bytes, mime, pages, content_hash(SHA-256),
               uploaded_by, note(무엇이 바뀌었나), created_at        unique(score, number)
Score (+)      current_version → ScoreVersion (지금 쓰는 판), last_version_number (번호 카운터)
```

- **054 계획과 다른 점**: 계획은 파일 필드를 Score 에서 ScoreVersion 으로 *옮긴다*였다. 대신 Score 의 파일 필드
  (`s3_key · size_bytes · mime · original_filename · pages · content_hash`)를 **지금 쓰는 판의 사본**으로 남겼다.
  목록 · 받기 · 처리 작업 · 기존 API · 웹이 판을 몰라도 그대로 돈다. 사본을 맞추는 곳은 `scores/services.py` 의 `_mirror` 하나
- **불변식**: 파일이 있는 악보는 판을 적어도 하나 가진다 — `Score.save()` 가 새 악보에 판 1 을 만든다(서비스 · 팩토리 · admin 어디서 만들어도)
- **판 번호는 늘기만 한다** — 판을 지워도 번호를 다시 쓰지 않는다(`last_version_number`). TV 는 판 번호로 받은 파일을 기억한다(S4).
  처음엔 `Max(number)+1` 이었고 테스트가 재사용을 잡았다
- **쿼터는 판을 올린 사람**에게. 악보를 지우면 판마다 올린 사람에게 돌려준다

## 2. 동작 (`scores/services.py` — API · 웹 공용)

| | |
|---|---|
| `add_version` | 새 판 → 곧바로 지금 쓰는 판. 쪽수 · 해시는 비우고 처리 작업이 채운다. `updated_at` 이 바뀐다(동기화 커서) |
| `make_current` | 예전 판으로 되돌린다(판은 남는다). 썸네일을 그 판으로 다시 |
| `delete_version` | 하나뿐이면 거부. 지금 판이면 남은 것 중 가장 최근 판으로. 쿼터 반환 · 파일 삭제 |
| `delete_score` | 모든 판 파일 삭제, 판마다 쿼터 반환 |

- 처리 작업(`process_pdf_info`)은 **읽은 파일의 판**에 쪽수 · 해시를 쓰고, 악보 행은 그 파일이 아직 지금 판일 때만 쓴다 —
  워커로 돌 때 읽는 사이 새 판이 올라와도 옛 파일 정보로 덮지 않는다. 채우면 `updated_at` 도 바꾼다
- 썸네일 서명 URL 에 판 번호를 넣었다 — 표지 파일 키는 같아서, 안 그러면 새 판 뒤에도 한 시간 동안 옛 썸네일이 캐시에서 나온다

## 3. API · 웹

- `GET/POST /api/v1/scores/{id}/versions/` (목록 · 새 판 `{upload_id, note}` — upload-url → PUT 다음), `DELETE …/versions/{n}/`,
  `POST …/versions/{n}/make_current/`. 악보 응답에 `version`(지금 판 번호) · `version_count`
- 웹 상세에 "판" 칸: 판마다 날짜 · 올린 사람 · 메모 · 파일 · 쪽/크기 · 보기 · 받기(`제목 (v2).pdf`) · 이 판으로 · 지우기, 새 판 올리기 폼.
  목록 카드 · 앙상블 파트 칩에 `판 N`/`vN` (2 이상일 때)
- admin: 악보에 판 인라인(읽기 전용 — 판 삭제는 쿼터 · 파일 때문에 서비스로만)
