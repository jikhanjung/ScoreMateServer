## 1. TV 앱이 따를 것

```
GET /api/v1/sync/scores/?cursor=<저장한 값>&limit=     (기기 토큰, 처음엔 cursor 없이)
→ { cursor, has_more, scores: [...], ids: [...] }

scores[i] = { id, title, composer, instrumentation, part_name, tags, note,
              ensemble: {id, name} | null,
              version: {number, sha256, size_bytes, pages, filename, created_at, note},
              download_url, updated_at }
```

1. `scores` 를 반영한다 — 가진 판(number · sha256)과 다르면 `download_url` 을 받는다(302 → 서명 URL, 5분).
   받은 파일의 SHA-256 이 `version.sha256` 과 같아야 채택한다. `sha256` 이 null 이면 아직 처리 중 — 다음 동기화에 다시 온다
2. **`ids` 에 없는 악보는 지운다** — 지워졌거나, 앙상블에서 나왔거나, 내보내졌거나, 앙상블이 지워졌거나, 개인 악보로 옮겨졌다
3. `cursor` 를 저장한다. `has_more` 면 곧바로 다시 부른다
4. 400 `{"cursor": …}` 면 커서를 버리고 처음부터. 401 이면 기기가 해제됐다 — 토큰을 지우고 연결 화면으로(059)

주기: 앱을 켤 때 · 앙상블 화면을 열 때 · 몇 분마다(가볍다: 변경 없으면 scores 는 빈 목록). 합주 중 실시간 동기화는 여전히 LAN 에서 TV 끼리.
`POST /api/v1/devices/me/heartbeat/ {app_version, model}` — 앱을 켤 때 · 업데이트 뒤.
`GET /api/v1/scores/{id}/download/?version=n` — 예전 판(선택).

## 2. 설계 — 054 계획과 다른 점

- **`deleted` 목록 대신 `ids`(지금 볼 수 있는 id 전부)**. TV 가 악보를 잃는 길은 삭제 말고도 나가기 · 내보내기 · 앙상블 삭제 ·
  개인 악보로 옮기기가 있다. 길마다 삭제 기록(소프트 삭제 · 묘비)을 남기면 하나를 빠뜨리기 쉽다. "지금 볼 수 있는 것 전부"는
  어떤 길로 잃든 맞고, 소규모 앙상블이라 id 몇백 개는 가볍다. 그래서 `Score.deleted_at`(소프트 삭제)도 두지 않았다
- **기준 시각 = max(updated_at, 내가 그 앙상블에 들어온 시각)** — 앙상블에 새로 들어가면 옛 악보가 "새로 보이게 된 것"으로 온다.
  앙상블을 지우면 그 악보들의 updated_at 을 올린다(올린 사람의 개인 악보로 돌아가 그 사람 TV 가 받게)
- **늦은 커밋 유예** `SYNC_LAG_SECONDS`(5초) — 커서를 넘긴 뒤 그보다 이른 시각으로 커밋되는 변경을 건너뛰지 않게 방금 것은 다음 번으로
- 커서 = (기준 시각, id) 불투명 base64. 같은 시각은 id 로 가른다. 한 번에 `SYNC_PAGE_SIZE`(200)
- 세트리스트 동기화는 2차(S6)

## 3. 그 밖
- `GET /api/v1/scores/{id}/download/` — 읽을 수 있으면 서명 URL 로 302 (파일은 nginx 가)
- `Device.last_synced_at` — 기기 토큰으로 동기화하면 남는다. 웹 TV 목록에 "동기화 …"
- 기기 API 뷰셋을 목록 · 조회 · 수정 · 해제만으로(목록 경로 POST 로 기기를 만들 수 없게), heartbeat 만 POST
