# P01 — 악보 인식(MusicXML)과 곡 단위 합주: 생각 정리

작성일: 2026-09-28
상태: 💭 구상 — 결정 전. 코드 없음. TV 앱 쪽 요청 문서(P07)는 **아직 쓰지 않는다**(생각을 더 정리한 뒤)

## 0. 요약
- **목적**: 스캔한 악보를 MusicXML 로. 직접 만든 악보는 Sibelius · MuseScore 에서 바로 내보내면 되므로 문제가 아니다.
  당장 필요한 것은 **마디 지도**이고, 굳이 이 작업을 하는 이유는 **음표 전체**다
- **실험**: Codex CLI(`gpt-6-astra`)로 Moldau0607 1~2쪽을 옮겼다. 구조 · 음 · 리듬 모두 맞았다(§1). 단 **깨끗한 Sibelius PDF 라서 가장 쉬운 경우**이고, 스캔본은 아직 해 보지 않았다
- **저작권**: 걸리는 자리는 변환이 아니라 **한 사람의 악보를 여럿이 보는 것**(TV 합주 모드의 LAN 전송)이다(§2).
  파트보 자동 생성도 같다 — **각자 가진 총보에서 자기 파트만 보여 주는 것은 깨끗하고**, 기기 사이에 보내는 것이 걸린다
- **방향**: 기기끼리는 파일 대신 **곡 id + 마디 번호**를 주고받고, 각 TV 는 **자기 악보**를 자기 마디 지도로 맞춘다(§3).
  파일이 오가지 않으니 저작권 문제가 풀리고, 각자의 주석도 그대로 남는다

## 1. 실험 — Astra 로 PDF → MusicXML (2026-09-28)

### 방법
- 호출 방식은 fsis2026 `scripts/astra_cli_bbox.py`(`docs/astra_cli_bbox.md`)와 같다:
  `codex exec --ignore-user-config --ephemeral --skip-git-repo-check --sandbox read-only --model gpt-6-astra
  -c model_reasoning_effort="high" --image … --output-schema … --output-last-message … --json -`
  - ChatGPT 로그인 경로를 쓰고 `OPENAI_API_KEY` · `CODEX_API_KEY` 는 뺀다(구독 한도 적용)
  - 로컬 `codex-cli 0.155.1`, 로그인 상태에서 돌렸다
- 입력: `MrgqPdfViewer/data/Moldau0607.pdf` 1~2쪽. 200dpi PNG 두 장을 한 번에 넣었다
- 출력 스키마: `{musicxml: string, measure_count: int, notes: string}`
- 지시: "MusicXML 4.0 score-partwise 로 전부 옮긴다. 인쇄된 파트 이름, 마디 번호, 음자리표, 조표, 박자표, 모든 음표 · 쉼표,
  붙임줄, 성부(`<backup>`)를 포함한다. **모든 성부의 마디 길이 합은 박자표와 같아야 한다.** 지어내지 말고,
  불확실한 곳은 notes 에 적는다"
- 스크립트: 스크래치 `omr/run.py`(호출) · `omr/check.py`(music21 검산). 저장소에는 아직 넣지 않았다

### 해석
- 깨끗한 인쇄 악보에서는 **음표 전체까지 실용적**이다. 마디 지도는 이 결과에서 그대로 뽑힌다(따로 만들 필요가 없다)
- ⚠️ **틀려도 그럴듯하다** — DiaRUGA OCR 의 교훈(학명이 조용히 다른 이름이 된 것)과 같다. 자동으로 잡을 수 있는 것과 없는 것:
  - **잡힌다**: 마디별 박 길이 합, 마디 수(TV 앱의 마디 검출이나 다른 파트와 대조), 파트 구성, 조표 · 박자표 흐름
  - **안 잡힌다**: 음높이. 사람의 검수 단계가 필요하다
- **아직 모르는 것**: 스캔본(기울어짐 · 번짐 · 손 표시)에서 버티는지. **실제로 쓸 스캔본으로 다시 돌려야 한다**.
  같은 파일을 Audiveris(오픈소스 OMR, MuseScore 로 열어 고치는 일반 경로)에도 넣어 비교 기준으로 삼는다.
  `~/projects/legato`(인쇄 악보용 OMR 모델, GPU 필요)도 후보다

### 도구 현황 메모
- MuseScore 에서 만든 악보는 MusicXML 내보내기가 기본 기능이다. **스캔 PDF → 악보는 MuseScore 4 에 없다**
  (MuseScore 3 의 PDF 가져오기는 Audiveris 를 쓰는 온라인 서비스였고 사실상 없어졌다)
- 일반적인 경로: Audiveris 로 인식 → MuseScore 로 열어 손으로 고친다

## 2. 저작권 (법률 자문 아님, 한국 저작권법 기준 대략)

| 악보 | MusicXML 변환 · 웹 재생 |
|---|---|
| 저작권 만료 곡 + 단원이 편곡(Moldau: 스메타나 1884년 사망, 편곡 전예완) | 문제없다 |
| 저작권 만료 곡의 출판 악보 스캔 | 대체로 괜찮다. 한국은 판면 자체를 보호하지 않는다. 단 창작적 교정판은 따로 보호될 수 있다 |
| 저작권이 살아 있는 곡, 또는 그 편곡을 산 악보 | 변환은 복제, 재생은 연주 재현이다. 권리자 허락이 필요한 영역이다 |

- **누가 듣는지**:
  - 혼자 연습용 → 사적이용 복제(제30조), 대체로 허용된다
  - 단원끼리 → 애매하다
  - 공개 → 허락 없이는 안 된다. ScoreMate 는 원래 공개 공유가 없다
- **AI 에 보내는 것**: 공개가 아니다. 계약 · 설정 문제다 — 개인 요금제라면 "모델 개선에 사용"을 끈다
- **가장 걸리는 자리 = TV 합주 모드**: 지휘자 TV 가 LAN 으로 PDF 를 나눠 준다(`FileServerManager`, 8080).
  저장은 막고 있지만, 산 악보를 **여러 명이 같은 시간에** 쓰는 것 자체는 그대로다. 산 악보는 보통 연주자마다 한 부 조건이다
### 파트보 자동 생성 (TV 앱 구상)
총보에서 한 파트만 떼어 보여 주는 것은 그 악보 일부의 **복제**다. 음이 그대로이므로 편곡(2차적저작물)은 아니다.
그래서 이 기능이 새 문제를 만들지는 않는다. **그 총보를 누가 정당하게 가지고 있고, 파트보가 기기 사이를 오가느냐**가 답을 정한다.

| 경우 | 판단 |
|---|---|
| **① 각 연주자가 자기 총보를 가지고 있고, 연주자 앱이 그 총보에서 자기 파트만 보여 줌** | **가장 깨끗하다.** 새로 나눠 주는 것이 없다. 자기 합법 사본을 보는 방식일 뿐이다(종이 총보에서 다른 줄을 가리고 보는 것과 같다). 화면 표시는 일시적 복제(제35조의2), 잘라 둔 이미지 캐시는 사적이용 복제(제30조)로 볼 수 있다 — 둘 다 원본이 합법 사본일 때. 각자 총보를 샀으니 파트 세트 구매를 대신하지도 않는다. 드물게 판매 조건에 기기 수 · 형식 제한이 있으면 그 계약은 따른다 |
| ② 앙상블이 권리를 가진 총보(저작권 만료 · 단원 편곡)를 서버 앙상블 악보로 두고, 각 단원 TV 가 **자기 계정으로 받은** 총보에서 자기 파트를 보여 줌 | 문제없다. 편곡자가 파트보를 뽑아 나눠 주는 것과 같다 |
| ③ 저작권이 살아 있는 곡의 총보 **한 부**로 파트를 만들어 **단원 기기로 보냄**(지휘자 TV → LAN) | **걸린다.** 출판사는 보통 총보와 파트 세트를 따로 팔거나 대여한다. 파트 세트 구매를 대신하는 셈이다 |
| ④ 저작권 만료 곡의 현대 출판본(교정판) | 한국은 판면을 보호하지 않아 대체로 괜찮다. 판매 · 대여 계약서에 복사 금지 조건이 있으면 계약 문제다 |

- **만드는 방식**:
  - 총보 이미지 자르기(TV `data/build_parts.py` 쪽)는 원래 판면을 그대로 옮긴다
  - MusicXML 에서 다시 그리기는 음만 가져와 새로 조판한다. 판면 보호가 있는 나라(영국 등)에서는 이쪽이 더 안전하지만, 한국에서는 차이가 거의 없다
  - 저작권이 살아 있는 곡이면 둘 다 복제다
- **원칙(안)**:
  - 파트보는 **각 기기가 자기가 가진 총보에서 그 자리에서 만드는 보기 방식**으로 둔다(①②)
  - **기기 사이에 파트보나 총보를 보내는 경로는 만들지 않는다**(③)
  - §3 의 곡 + 마디와 그대로 맞는다: 각자 자기 총보를 곡에 연결하고 **보여 줄 파트**만 정하면, 합주 때는 `work_id + 마디`로 맞춘다

### 서버에서 해 둘 만한 것
- MusicXML · 재생도 본인과 앙상블 단원에게만
- 분석을 요청할 때 "저작권 만료 · 직접 제작 · 허락받음" 확인 체크
- 오디오 파일 공개 링크는 만들지 않는다

## 3. 곡 단위 합주 — 파일이 아니라 "곡 + 마디"

### 문제
"서버에서 받은 악보를 각자 계정으로 열게 하자"(1안)는 **메타데이터가 정확해야만** 된다.
각자 산 악보에 각자 주석을 달면 PDF 가 다르다. 그러면 **sha256 도 score_id 도 다르다** — 파일로는 같은 악보인지 알 수 없다.

### 관찰
- 합주에서는 어차피 **파트마다 악보가 다르다**. 쪽 수도, 넘기는 위치도 다르다
- TV 메트로놈은 이미 "각 기기가 **마디**를 보고 스스로 넘김"이다(MrgqPdfViewer 050 · P03)
- 그러니 기기끼리 필요한 것은 파일이나 쪽이 아니라 **같은 곡이라는 것 + 마디 번호**다

### 구상
- **곡(Work)** — 앙상블 안의 항목(파일 없음)
  - 제목, 작곡가, 편곡 · 판본
  - 기준 마디 지도: 마디 수, 박자표 · 템포 변화, 도돌이표 · D.S. · Coda, 리허설 마크
- **악보 → 곡 연결**
  - 개인 악보든 앙상블 악보든 `work` 하나 + `part_name`
  - 누구의 파일이든 곡을 가리킬 수 있다 — 각자 산 악보, 각자 주석
- **연결은 사람이 한 번 확인**
  - 제목 · 작곡가 · 파트 이름이 비슷하면 후보로 보여 준다
  - 마디 지도가 있으면 **마디 수와 박자표 흐름이 같은지 비교해 판본을 검사**한다. 주석은 마디 구조를 바꾸지 않는다
  - 마디 번호가 어긋나면(다른 판본) 경고한다. 결정은 사람이
- **TV 동기화**: 악보마다 `work_id` · `part_name` · 마디 지도(분석)를 싣는다
- **합주 프로토콜**(TV 앱, 나중에): `work_id + 마디`
  - 각 TV 는 그 곡에 연결된 **자기 악보**를 열고, 자기 마디 지도로 마디 → 쪽 위치를 바꾼다
  - LAN 파일 전송은 **곡에 연결되지 않은 로컬 파일에만** 남긴다

### 이 방식으로 얻는 것
- **저작권**: 파일이 하나도 오가지 않는다. 각자 자기가 산 악보로 연주한다
- **주석 보존**: 각자 자기 표시를 본다
- **판 불일치 방지**: 연결할 때 마디 구조를 검사한다
- **OMR 과 이어진다**: 스캔본도 Astra 분석에서 마디 지도가 나오므로 곡에 연결하고 판본을 검사할 수 있다.
  "마디 지도 먼저"의 이유가 여기에 있다
- **곡 단위 세트리스트(나중)**: 곡목 하나가 각자의 파트 악보로 풀린다

### 서버에 이미 있는 것
- `Score.ensemble` · `part_name`, ScoreVersion(판), 판별 분석(`ScoreAnalysis`, `analyzer` 이름 · sha256 확인), 동기화 API

## 4. 서버 붙이기 구상 (OMR, 실험 결과가 좋을 때)
- 새 판이 올라오면 대기열에 넣는다 → **호스트 워커**가 쪽 단위로 Astra 를 부른다
  - fsis2026 · ocrserver 처럼 호스트 cron 에서 돌린다. 컨테이너에는 codex 를 넣지 않는다
  - fsis 교훈: 비대화형 셸의 nvm PATH, 치명 오류는 첫 건에서 멈춤, 소스 키(이미지 sha256 + 프롬프트 sha256)
- 쪽 단위 결과를 이어 붙인다. 쪽 경계의 붙임줄 · 마디 번호를 검사해야 한다
- 검산을 통과한 결과만 판별 분석으로 저장한다(예: `analyzer="astra-musicxml"`, `"measure-map"`)
- 웹 악보 화면: "MusicXML 받기 / 검수 필요" 표시. 음높이 검수 화면은 별도 과제

## 5. 열린 질문
1. **스캔본 실험** — 실제로 쓸 스캔 악보 한두 부로. Astra 와 Audiveris 비교
2. **곡을 어디에** — 앙상블 안(단원이 함께 관리)이 맞아 보인다. 개인 악보만 쓰는 사용자는?
3. **마디 지도가 없는 악보** — 연결만 하고 판본 검사는 건너뛸지, 연결 전에 분석을 먼저 돌릴지
4. **파트별 마디 지도 비교 규칙** — 파트 악보의 여러 마디 쉼표 묶음, 컷 · 반복 표기 차이, 못갖춘마디(마디 0)
5. **이용 범위 표시** — 악보마다 "공유 가능 / 개인용(산 악보)"을 둘지, 기본값은 무엇으로
6. **음 검수** — 누가, 어떤 화면에서(MuseScore 로 내려받아 고쳐 다시 올리기? 웹 미리 보기?)
