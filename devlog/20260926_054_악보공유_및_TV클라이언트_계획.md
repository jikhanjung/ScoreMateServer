## 0. 배경 — 목적이 바뀌었다

2025-08 의 MVP 는 **개인 악보 보관함**이었다 (`ARCHITECTURE.md`: *Private by default*, *No server-side sharing*).
2026-09 에 정한 목적은 **앙상블 안에서 악보 공유**다:

- 리더(지휘자 · 악보 담당)가 곡 · 파트보를 올리면 **멤버의 Google TV(MrgqPdfViewer)에 자동으로 배포**된다
- 수정판이 잦다 (`블타바_0829_42페이지까지`, `완판수정_아르페지오네(도돌이풀기)0826` — 지금은 파일 이름으로 판을 구분한다) → **버전 관리**
- TV 는 리모컨뿐이다 → **TV 코드 + QR 로 기기 연결** (RFC 8628)
- 합주 중 실시간 동기화(박 · 마디 · 페이지)는 지금처럼 **LAN 에서 TV 끼리** 한다 — 서버는 실시간 경로에 없다 (원래 원칙 유지)

그래서 원칙을 이렇게 바꾼다: **개인 악보는 비공개, 앙상블에 올린 악보는 그 앙상블 멤버에게만.** 공개 공유는 하지 않는다 (편곡 악보는 저작물).

## 2. 데이터 모델 (추가 · 변경)

```
Ensemble        id, name, created_by → User, created_at
Membership      ensemble, user, role(owner|leader|member), part(선택, 예 "Guitar 1"), joined_at
                unique(ensemble, user)
Invite          ensemble, code(짧은 난수), created_by, expires_at, max_uses, uses   ← 링크로 가입

Score (변경)    + ensemble → Ensemble (null = 개인 악보)
                + part_name (선택, "총보" · "Guitar 1" …)
                + current_version → ScoreVersion
                + deleted_at (소프트 삭제 — 동기화가 "지워졌음"을 알려야 한다)
                  기존 s3_key · size_bytes · pages · content_hash 는 current_version 으로 옮긴다 (데이터 마이그레이션)
ScoreVersion    score, number(1,2,…), s3_key, size_bytes, pages, content_hash, uploaded_by, note, created_at

Setlist (변경)  + ensemble (null = 개인)

Device          id(uuid), user, name(“거실 TV”), model, app_version, created_at, last_seen_at, revoked_at
DeviceAuthorization
                device_code(해시 저장), user_code(8자, 헷갈리는 글자 제외 “BCDF-GHJK”), device_name,
                status(pending|approved|denied|expired), user(승인한 사람), expires_at(10분), interval(5초), last_polled_at
```

권한:
- 개인 악보: 올린 사람만
- 앙상블 악보: **멤버 읽기**, **owner · leader 쓰기**(올리기 · 새 버전 · 지우기)
- 쿼터: 올린 사람 기준 (MVP). 앙상블 쿼터는 나중에

## 3. TV 기기 연결 (RFC 8628)

```
TV                                   서버                                   휴대폰 브라우저
POST /api/device/code {name,model} ─▶ device_code, user_code, verification_uri,
                                      verification_uri_complete(=…/activate?code=BCDF-GHJK), interval
화면: 코드 + QR(verification_uri_complete)
                                                                ◀── /activate (로그인 필요) → 코드 확인 → "이 TV 연결" 
                                     DeviceAuthorization.approved, Device 생성
POST /api/device/token {device_code} (interval 마다)
   ├ 428/“authorization_pending”
   ├ 429/“slow_down”
   └ 200 {access, refresh, device_id} ─ 이후 일반 API 를 JWT 로
```
- 기기 토큰: refresh 수명을 길게(예: 180일) + `device_id` 클레임. 웹 "내 기기"에서 **해제** → `revoked_at` → refresh 거부
- `/activate` 는 Next.js 페이지. 로그인 안 돼 있으면 로그인 후 돌아온다
- 무차별 대입 방지: user_code 조회에 속도 제한, device_code 는 해시로만 저장

## 4. 동기화 API (TV 용)

```
GET /api/sync/scores?cursor=<opaque>
→ { cursor: "<다음에 보낼 값>",
    scores:  [{ id, title, composer, ensemble:{id,name}, part_name,
                version:{number, sha256, size_bytes, pages, created_at, note},
                updated_at }],
    deleted: [id, …] }
GET /api/scores/{id}/download   → 302 로 짧은 presigned GET URL (TV 가 저장소에서 직접 받는다)
POST /api/devices/me/heartbeat {app_version, synced_cursor}   (선택 — 웹에서 "마지막 동기화" 표시)
```
- 커서 = 마지막으로 본 `updated_at` + id (단조). 버전이 올라가거나 메타데이터가 바뀌면 `updated_at` 이 바뀐다
- 첫 동기화는 cursor 없이 전체
- 범위: **내 개인 악보 + 내가 멤버인 앙상블의 악보**. 앙상블에서 나가면 그 악보들이 `deleted` 로 온다
- 세트리스트 동기화는 2차

## 6. 배포 — dolfinid (GCP VM, 여러 프로젝트가 함께 씀)

**dolfinid 의 방식** (hanyang3d `deploy/` 로 확인):
- VM 의 **nginx** 에 프로젝트별 사이트 설정(`deploy/host/<프로젝트>.nginx.conf`), Let's Encrypt(`/srv/<프로젝트>/acme` webroot), `*.nopeoplestime.info` 서브도메인
- 이미지는 빌드 호스트에서 `honestjung/<프로젝트>:vX.Y.Z`(linux/amd64)로 올리고, VM 은 `/srv/<프로젝트>/` 의 compose 가 `127.0.0.1:<포트>` 로만 연다
- DB 는 **SQLite** 파일(bind mount) — 배포 전 검증 백업, 컨테이너 안에서 migrate, 실패하면 이전 `.env` 로 되돌림(`deploy.sh`)
- `deploy.toml` 규약(instance · image · version · targets.prod: host=dolfinid, root=/srv/…, expose=127.0.0.1:…), 읽기 전용 컨테이너 · `cap_drop: ALL` · 로그 크기 제한 · 로그인 요청 제한
- Gunicorn 2 workers × 4 threads 수준의 가벼운 구성

**지금의 `docker-compose.prod.yml` 은 VM 을 혼자 쓰는 구성**이다 (nginx 컨테이너가 80/443, Postgres · Redis · Celery · MinIO 별도). 그대로는 VM 의 nginx 와
포트가 부딪히고 공용 VM 에 컨테이너 5~6개가 늘어난다. dolfinid 방식에 맞춰 줄인다:

| | 지금 | dolfinid 용 (제안) |
|---|---|---|
| 프록시 · TLS | nginx 컨테이너 | VM nginx 에 `scoremate.nopeoplestime.info`(가칭) 블록 + certbot |
| DB | Postgres 컨테이너 | **SQLite** (bind mount, 배포 전 백업). 소규모 앙상블 용도에 충분. `Score.tags` 의 Postgres 전용 `ArrayField` → `JSONField` |
| 백그라운드 | Redis + Celery 워커 | **없앤다** — 페이지 수 · 썸네일은 업로드 확인 때 PyMuPDF 로 바로(수백 ms). 나중에 필요하면 그때 |
| 파일 | MinIO(S3) | VM 디스크 `/srv/scoremate/files` + **nginx `X-Accel-Redirect`** 로 다운로드(권한은 Django 가 검사, 전송은 nginx). 백업은 SQLite 와 함께. 용량이 커지면 GCS(S3 호환, 지금 boto3 코드) 로 |
| 웹 | Next.js 서버 | `next build` 정적 내보내기(`output: 'export'`)를 nginx 가 서빙 — Node 프로세스 없음. 불가능한 화면이 있으면 Next 컨테이너 하나 |
| 컨테이너 | 6개 | **1개** (Gunicorn) |

포트는 VM 에서 비어 있는 것을 확인해 정한다(`ss -ltnp`; hanyang3d 가 8013 · 8015).

## 8. 결정 (2026-09-26)
- **DB = SQLite, 파일 = VM 디스크** (`/srv/scoremate/`, dolfinid 관례). 다운로드는 nginx `X-Accel-Redirect`
- **도메인 = `scoremate.noematica.kr`** — DNS 는 이미 dolfinid(34.64.158.160)를 가리킨다
- **이미지 = `honestjung/scoremateserver:vX.Y.Z`** (linux/amd64, Docker Hub) — 다른 서비스와 같이 빌드 호스트에서 만들어 올리고 VM 은 받아서 실행
- **포트 = `127.0.0.1:8016`** — VM 에서 127.0.0.1 로 쓰는 포트가 8002 · 8010~8015 (2026-09-26 `ss -ltn` 확인)
- VM 여유: 메모리 7.9GB 중 가용 6.4GB, 디스크 32GB, CPU 2
- **로그인은 1차에 기존 이메일 · 비밀번호**. Google 로그인은 2차(S6)
- 앙상블 쿼터는 두지 않는다(올린 사람 기준) — 필요해지면 그때
