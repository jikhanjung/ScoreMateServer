## 요청
"PDF 파일명 말고 곡 제목, 작곡가 등 메타데이터를 입력할 수 있게 해줘. PDF 에서 추출해도 되고."

운영 악보 제목이 파일 이름 그대로였다(`SM-000234705_02052026`, `블타바_0829_42페이지까지` …).
고치기 화면은 이미 있었지만 **작곡 · 편곡이 한 칸**이었고, PDF 에 들어 있는 정보를 쓰지 않았다.

## 바꾼 것
- **`Score.arranger`**(편곡) 칸 — 마이그레이션 `0006`. 웹 칸 이름: "작곡 · 편곡" → **"작곡"** + **"편곡"**
  - 화면: 상세 · 카드 · 검색(편곡자로도 찾음)
  - API: 악보 serializer 4곳 · 동기화 응답에 `arranger` 추가
- **`scores/pdfmeta.py`**
  - `read()`: PDF 문서 속성 dict. 깨진 PDF 면 `{}` — 올리기를 막지 않는다
  - `suggest()`: 제목 제안
    - 뜻 없는 제목은 버린다: Untitled, `Microsoft Word - …`, 파일 이름 같은 것
    - 끝의 " - 파트" 는 **총보 · 악기 이름일 때만** 파트로 떼어 낸다(40자 이하) — 부제목("Suite - Prelude and Fugue")을 자르지 않게
- **올리기**: 제목을 비우면 PDF 문서 제목, 그것도 없으면 파일 이름
  - 여러 파일에 제목을 주면 지금처럼 파일 이름이 파트다
  - Author 는 **자동으로 채우지 않는다** — 작곡가인지 편곡자인지 알 수 없다
- **고치기 화면 "찾은 정보"**: 출처마다 값 목록과 "채우기" 버튼. JS 가 칸만 채우고, 저장은 사람이 한다
  - PDF 문서 정보: 제목 · 파트 · (Author → 편곡 제안)
  - 악보 인식이 첫 쪽에서 읽은 것: 제목 · 작곡 · 편곡 · 편성 · 파트
- **OMR 레인**: `astra_musicxml.py` 가 조각 전사 전에 **첫 쪽 곡 정보 호출**(effort medium, 스키마 고정)을 먼저 한다
  - 받는 것: title · subtitle · composer · arranger · lyricist · instrumentation · part_name · parts · notes
  - 지시: "인쇄된 것만, 일반 지식으로 짐작하지 말 것"
  - 흐름: `metadata.json` → `result.json` → 레인 bundle → `omr_ingest` → 분석 `data.metadata`
  - **인식이 실패해도 남긴다**
