# 068 — 보표 · 마디 분석 파일: TV 앱 분석을 서버로 옮김 (0.10.0)

작성일: 2026-09-28
상태: ✅ 구현 · 테스트 · 배포

## 요청
"앱의 소스를 살펴보고 그 로직을 그대로 가져와서 PDF 에서 보표 및 마디를 분석한 정보를 파일로 저장해줘.
나중에 musicxml 파일하고 같이 앱에 동기화 할 수 있게." — "분석은 kotlin 쪽의 소스를 기준으로 작업해야 돼."

## 기준 = Kotlin (파이썬 원본이 아니라)
앱의 `data/segment_score.py`(2026-06)는 출발점이다. 지금 앱은 그 뒤로 많이 달라졌다:
- MuseScore 형식 지원(#056)
  - 오선 조각 합치기
  - 보표 사이를 잇는 연결선으로 시스템 나누기
  - SMuFL 음표 머리 · 박자 숫자
  - 보표 2~3개 시스템 규칙
- 끝세로줄 15pt 규칙(#049)
- 보표 이름(P07)
- C · ¢ 기호 박자표

그래서 `app/src/main/java/com/mrgq/pdfviewer/score/` 를 옮겼다:

| Kotlin | 파이썬(`scores/score_layout.py`) |
|---|---|
| PathContentInterpreter.kt | `ContentInterpreter` — 콘텐츠 스트림을 직접 읽는다. 끝점만 · `re` 네 모서리 · q/Q · Form XObject(깊이 8) · 텍스트 BT/Tf/Td/TD/Tm/T*/TL/Tj/TJ/'/" |
| PdfBoxContent.kt | `Resources` · `page_content` — PyMuPDF 는 스트림 압축 해제 · XObject · 글꼴(ToUnicode CMap, simple 글꼴 Differences) 조회에만 |
| StaffSystemDetector.kt | `detect_systems` · `_build_system` · `_merge_segments` · `cluster` |
| StaffLabelDetector.kt | `attach_labels` |
| TimeSignatureDetector.kt | `detect_time_signatures` |
| ScoreLayoutAnalyzer.kt · ScoreLayout.kt | `analyze` · `to_measures` · `to_staves` |

- 임계값 · 규칙 · 반올림을 바꾸지 않았다
  - 앱의 Float(32비트) 계산을 `f32()` 로 흉내 낸다
  - `round1` 은 Kotlin `Math.round`(0.5 에서 위로)와 같다
- 글꼴 해독은 PdfBox `toUnicode` 대신 ToUnicode CMap 을 직접 읽는다. 없으면 simple 글꼴의 ASCII + Differences 로 한다

## 파일
- 판마다 `{user}/scores/{score}/layout/v{N}.json`
  - `format: scoremate-score-layout`, `format_version: 1`, `source`, `pdf_sha256`
  - `pages[pageIndex, widthPt, heightPt, systems[top, bottom, left, right, staffBands, barlines, staffLabels], timeSignatures[…]]`
  - `measures` = 앱 **ScoreMeasure** 행(measureNumber · pageIndex · systemIndex · left/top/right/bottomPt · pageWidth/HeightPt · timeSigNumerator/Denominator)
  - `staves` = 앱 **ScoreStaff** 행(pageIndex · systemIndex · staffIndex · top/bottomPt · label). `pdfFileId` 만 앱이 붙이면 그대로 넣을 수 있다
- 분석 행: `ScoreAnalysis(analyzer='score-layout')`
  - data: 키 · sha256 · 크기 · 쪽/시스템/마디 수 · 박자표 목록 · 이름 목록 · source
  - 판 · 악보를 지우면 파일도 지운다(`omr.stored_keys` 가 두 종류를 모두 모은다)
- 동기화
  - `sync/scores` 의 각 악보에 `layout {url, sha256, size_bytes, filename(PDF 이름.layout.json), format_version, measures, systems, updated_at}`
  - 받기: `GET /api/v1/scores/{id}/layout/` → 서명 URL 302. MusicXML 과 같은 방식이다
- 웹 상세: "보표 분석: N시스템 · M마디 · 박자표". 악보 인식 마디 수와 다르면 함께 보인다(도돌이 · 못갖춘마디로 다를 수 있다)

## 언제 도나
- 처음엔 PDF 처리 작업 끝에 붙였다 → 테스트가 80초 → 430초(올릴 때마다 35쪽 분석)
- 운영 올리기도 수 초 늦어진다 → **호스트 cron 레인** `deploy/host/layout_lane.sh`(5분, flock, `manage.py score_layout` = 분석 없는 판 전부)
  - 분석은 컨테이너 코드가 한다(모델 호출 없음)
- `manage.py score_layout --version-id N` 으로 그 판을 다시 한다
