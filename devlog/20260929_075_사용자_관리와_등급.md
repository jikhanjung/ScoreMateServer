# 075 — 사용자 관리와 등급 (0.13.0)

작성일: 2026-09-29
상태: ✅ 백엔드 테스트 511 통과

## 요청
- "사용자 권한 기능을 추가해줘. admin 은 superuser 역할이니 사용자 관리를 할 수 있어야겠지."
- "나중에 사용자 등급도 필요할 테고."

## 권한 — 두 단계
| 역할 | 무엇 | 필드 |
|---|---|---|
| 관리자 | 사용자 관리(웹 `/manage/users/` · API `/api/v1/admin/users/`) + Django 관리 화면(`/admin/`) | `is_superuser` (= `is_staff`, 함께 켜고 끈다) |
| 사용자 | 자기 악보 · 세트리스트 · 기기, 속한 앙상블 | — |

- 앙상블 안의 역할(owner · leader · member)은 그대로다(055). 이것은 서비스 전체의 권한이다
- 관리 API 는 전에는 `IsAdminUser`(is_staff)였다 → **superuser 만**. PATCH 도 같은 규칙을 거친다
  - `is_staff` · `used_quota_mb` 는 읽기만(쓸 수 있으면 규칙을 건너뛴다)

## 등급 — `User.plan` 을 쓴다
| 키 | 이름 | 기본 저장 공간 |
|---|---|---|
| solo | 기본 | 200MB |
| pro | 프로 | 1,000MB |
| enterprise | 단체 | 5,000MB |

- `settings.USER_GRADES` — 환경 변수 `GRADE_SOLO_MB` · `GRADE_PRO_MB` · `GRADE_ENTERPRISE_MB` 로 바꿀 수 있다
- 등급을 바꾸면 그 기본 한도가 들어간다. 한도를 따로 적으면 그 값(사용자별 예외)
- 지금 등급은 **저장 공간만** 정한다. 기능 제한(예: 기기 수, 악보 인식 쪽수)은 나중에 이 표에 칸을 더한다
- 필드 · 선택지는 그대로라 마이그레이션 없음

## 규칙 — `core/services.update_user` 한 곳(웹 · API 가 같이 쓴다)
- 관리자(활성)만 바꿀 수 있다 — 아니면 `PermissionDenied`
- 자기 자신의 관리자 권한을 뺄 수 없다. 자기 자신을 사용 중지할 수 없다
- **활성 관리자는 적어도 한 명** 남는다(다른 관리자를 내리거나 중지할 때도)
- 사용 중지(`is_active=False`)
  - 웹 세션이 끝나고 로그인이 막힌다(Django 인증이 비활성 사용자를 거부)
  - 기기의 access · refresh 토큰이 모두 401(simplejwt 가 비활성 사용자를 거부) — 기기 연결을 해제하지 않아도 된다
  - 악보 · 파일 · 기기 연결은 그대로 — 다시 허용하면 이어서 쓴다

## 웹
- 상단 메뉴 "사용자 관리"(관리자에게만). 관리자가 아니면 주소를 알아도 404
- 목록: 이름 · 이메일 · 등급 · 저장 공간(사용/한도/%) · 악보 수 · 기기 수 · 가입 · 마지막 로그인 · 상태. 이름 · 이메일로 찾기, 50명씩
- 사용자 화면: 정보 + 연결 기기, 바꾸기(등급 · 한도 · 관리자 · 사용 중)
  - 자기 자신이면 관리자 · 사용 중 칸이 잠긴다

메뉴 · 404, 편집 폼, API 가 규칙을 거친다 · staff 만으로는 403

## 남은 것
- 등급별 기능 제한(기기 수 · 인식 쪽수 등) — 필요해지면 `USER_GRADES` 에 칸을 더하고 `core/services` 에서 검사
- 사용자 삭제는 두지 않았다(악보 · 파일 정리가 따른다) — 사용 중지로 충분한지 지켜본다
- 관리자가 비밀번호를 다시 정하는 것은 API(`reset_password`)만 — 웹에는 아직 없다
