## 결정
- 모델 호출(Codex CLI `gpt-6-astra`, ChatGPT 로그인)은 **운영 호스트 cron** 이 한다. 컨테이너에는 codex 를 넣지 않는다.
  fsis2026 · ocrserver 의 방식 그대로다: 호스트는 파일만 만들고, 앱이 받아서 올린다
- 로컬로 PDF 를 가져와 돌리는 길은 쓰지 않는다. 운영 데이터는 운영 호스트 밖으로 나가지 않는다(모델 호출 제외)
- 결과는 **그 판의 분석**(`ScoreAnalysis`, `analyzer=astra-musicxml`)이다. MusicXML 은 커서(분석 data 1MB 제한) 저장소 파일로 둔다
  (`{user}/scores/{score}/omr/v{N}.musicxml`). data 에는 키 · sha256 · 파트 · 마디 수 · 박자표/조표 바뀌는 곳 · 실행 기록만
- 실패도 분석 행(`status=failed`)으로 남긴다 — 같은 판을 계속 부르지 않게. 다시 하려면 admin 에서 지운다

## 흐름
```
*/10 cron → /srv/scoremate/scripts/omr_lane.sh      (flock, 한 번에 판 하나)
  1. manage.py omr_pending   → OMR_JOB {version_id, key, sha256, …}   지금 쓰는 판 · 해시 있음 · 인식 기록 없음 · 오래된 것부터
  2. files/<key> 의 sha256 확인 → omr/venv/bin/python scripts/astra_musicxml.py <pdf> omr/work/v<id>
  3. result.json + score.musicxml → JSON | manage.py omr_ingest   (sha256 을 한 번 더 확인)
```

## scripts/astra_musicxml.py
- fsis2026 `astra_cli_bbox.py` 와 같은 호출:
  - `codex exec --ignore-user-config --ephemeral --sandbox read-only --output-schema --output-last-message --json`
  - API 키 환경변수는 뺀다
- **2쪽씩** 부른다(200dpi). 둘째 조각부터는 앞 조각의 **파트 목록 · 마지막 마디 번호 · 조표/박자표/음자리표/divisions** 를 넘긴다.
  각 조각의 첫 마디는 attributes 를 다 적게 하고, 합칠 때 앞 상태와 같은 것만 지운다(바뀐 것은 남는다)
- 조각마다 검산:
  - well-formed
  - 파트 구성이 첫 조각과 같음
  - 파트끼리 마디 수가 같음
  - music21 로 성부마다 박 길이 합 = 박자표(처음 · 끝 마디의 못갖춘마디, 온쉼표 마디는 허용)
  
  실패하면 오류를 붙여 한 번 더 부른다. 그래도 실패하면 멈춘다(종료 3 = 판정, 다시 안 부름)
- 이어 하기: 끝난 조각(`chunks/NNN_pX-Y/chunk.musicxml`)은 다시 부르지 않는다
- 종료 코드:
  - 0 = 성공
  - 3 = 검산 실패(기록)
  - 그 밖 = 실행 못 함(codex · 로그인 · 시간 초과). 레인이 다음 cron 에서 다시 하고, 3번 넘으면 실패로 기록

## 서버 · 웹
- `scores/omr.py`: `pending` · `job` · `ingest` · `measure_summary` · `musicxml_of` · `stored_keys`
- 관리 명령:
  - `omr_pending`: 출력 줄 머리가 `OMR_JOB ` — 앱 시작 메시지가 stdout 에 섞여도 안전하다

  - PDF 와 같은 권한, 5분짜리 서명 URL
  - 실패하면 "악보 인식 실패"로 표시
- TV 동기화의 `analyses` 목록에도 `astra-musicxml` 이 보인다. data 에 MusicXML 자체는 없다
